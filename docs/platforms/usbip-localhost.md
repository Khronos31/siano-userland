# localhost usbip / VHCI での検証結果

> [!WARNING]
> - 本文書は隔離環境における実験記録であり、ロード済み `smsusb` との live handoff や試験後の再バインドを通常運用手順として推奨するものではない。
> - 試験を再現する場合は、チューナー接続前に blacklist を有効化する。
> - すでにモジュールが bind している場合は、設定反映後に OS を再起動する。

## 検証環境

- 検証対象: `siano-userland` Stable v0.1.5 x86_64 配布アーカイブ（SHA-256: `b5528d9f179574b93a2982390d295c595332bf16d1bb60836de775b0c693d931`）
- ホストハードウェア: Latitude 5300
- OS: AnduinOS（Linux 7.0.0-31-generic、usbip 2.0）
- 使用チューナー: PX-S1UD 2台

## 構成手順の要点

- 専用の network namespace を作成し、その loopback インターフェース上でのみ `usbipd` を起動する。
- 物理USBデバイス2台を export し、ホスト側の別々の VHCI ポートへ attach する。
- export元の物理ノードとVHCIノードを識別するため、VHCI側のデバイスノードを事前オープンし `--fd` で渡す。

## 検証結果

- VHCI経由のデバイスノードを指定した60秒gate試験および30分soak試験が合格した。
- 30分連続受信実績:
  - T22: 3,885,441,120バイト / 20,667,240パケット
  - T21: 3,885,226,800バイト / 20,666,100パケット
- 188バイト余剰、syncエラー、TEI、キュー破棄、致命的エラーはすべて0件であった。
- プロセスリソースは各プロセスともRSS 5,288 KiB、ファイルディスクリプタ数 7 で一定に推移した。
- 試験終了後にTCP 3240ポート、network namespace、VHCIポート、プロセスの残留がないことを確認した。
- 試験時の観測事項として、両デバイスにおけるカーネル標準ドライバ `smsusb` のバインド復元を記録した（通常運用における推奨手順とは区別される）。

## 適用範囲と境界

- 検証実績: 同一Linuxホスト内におけるlocalhost/VHCI経由の通信経路。
- 再検証対象: 物理ネットワーク（LAN）を経由するリモートusbip構成、および通信途絶・切断注入試験。
